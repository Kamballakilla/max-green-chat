# Как будем разбирать проект

Идём маленькими шагами. Один шаг — один небольшой фрагмент, объяснение каждой строки, изменение своими руками и короткая проверка понимания.

1. **Запуск:** `package.json`, зачем нужны Node, npm, зависимости и команды.
2. **Вход в приложение:** `index.html` → `main.tsx` → `App.tsx`. DOM, JSX, компоненты, StrictMode.
3. **Типы:** `Credentials`, `Chat`, `Message`. Что TypeScript проверяет до запуска, а чего не знает про ответы сервера.
4. **Форма:** один input из `Login.tsx`. `useState`, value, onChange, controlled input, onSubmit.
5. **Валидация:** `normalizePhone`, регулярные выражения, исключения. Меняем тест и смотрим результат.
6. **HTTP:** один запрос `sendMessage`. URL, POST, JSON, Promise, async/await, ошибки.
7. **Состояние:** один переход `chatReducer`. Неизменяемость, map, spread, dispatch.
8. **Интерфейс:** как массив сообщений становится JSX, зачем key и почему текст безопасен.
9. **Получение:** одно уведомление от ReceiveNotification до DeleteNotification.
10. **Жизненный цикл:** useEffect, AbortController, очистка, StrictMode, последовательная очередь.
11. **Надёжность:** повторные события, ранние статусы, сетевые ошибки, черновики.
12. **CSS и адаптивность:** flex/grid, размеры, overflow, мобильные экраны.
13. **Тесты:** один тест в деталях, затем пишем свой сценарий.
14. **Защита решения:** объясняем компромиссы и самостоятельно добавляем небольшую функцию.

Начнём разбор после запуска и просмотра результата. Цель — понимать решение и уметь менять его без подсказки.
