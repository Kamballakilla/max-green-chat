# Проверка перед сдачей

## Автоматически

`npm run check` запускает линтер, тесты и production-сборку. Тесты проверяют нормализацию телефона, адрес API, контракты fetch, разбор уведомлений, повторную доставку, ранние статусы, последовательность polling, остановку при 401, отправку в демо, создание чата, лимит текста и сохранение черновика при ошибке.

В тестах GREEN-API заменён контролируемыми ответами. Реальные ключи не нужны.

## В браузере

- Открыть демо. Отправить текст, дождаться автоматического ответа.
- Создать диалог по корректному номеру. Повторно открыть тот же номер: дубликат не создаётся.
- Ввести короткий/некорректный номер: увидеть понятную ошибку.
- Написать черновик, переключить диалог и вернуться: текст сохранён.
- Проверить Enter, Shift+Enter, пустую строку и текст длиннее 4000 символов.
- Найти чат по имени и номеру, проверить пустой результат поиска.
- Прокрутить историю вверх: новые сообщения не должны принудительно возвращать вниз.
- Открыть на ширине 390 px: список → диалог → кнопка назад.
- Пройти формы клавишей Tab. Открыть диалог, закрыть Escape, убедиться в возвращении фокуса.
- Выйти: увидеть экран подключения без ключей и переписки.

## С реальным инстансом — обязательно перед сдачей

Эта проверка требует данных владельца. В ходе автоматической сборки реальный инстанс не подключался.

1. Подготовить отдельный авторизованный MAX-инстанс по README.
2. Отключить другие потребители его очереди. Проверить тариф и разрешённых получателей.
3. Ввести неверный токен: приложение должно показать ошибку без раскрытия токена.
4. Подключиться с правильными данными, создать чат по номеру второго аккаунта.
5. Отправить «Проверка связи» и убедиться, что текст появился на телефоне получателя.
6. Ответить с телефона. Убедиться, что ответ появился **в том же чате**, без повторов.
7. Отправить несколько ответов подряд. Проверить очередь, порядок и отсутствие дублей.
8. Проверить статусы доставки/прочтения при включённых webhook-настройках.
9. Временно отключить сеть: клиент показывает сбой; после восстановления снова получает сообщения.
10. При сетевом сбое отправки проверить черновик и статус «неизвестен». Перед повтором посмотреть MAX, чтобы не отправить дубликат.
11. Выйти и проверить, что polling прекратился. Повторить на опубликованном домене, если сайт размещён.

Если браузер блокирует запросы из-за CORS, проверить apiUrl и политику сервиса. Не отключать защиту браузера; для среды без прямого CORS потребуется отдельно реализовать backend-прокси.
