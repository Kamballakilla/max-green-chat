# MAX Chat

**Опубликованное приложение:** https://kamballakilla.github.io/max-green-chat/

GitHub Pages автоматически обновляется после push в `main`: workflow проверяет проект, собирает `dist/` и публикует сайт. Для проверки без ключей нажмите «Открыть демо».

Простой клиент личных текстовых диалогов в MAX через GREEN-API. Тестовое задание на React: подключение инстанса, создание чата по телефону, отправка сообщения и получение ответа.

**Быстрая проверка без аккаунта:** запустите проект и нажмите **«Открыть демо»**. Демо работает локально, не использует сеть и явно отделено от реальной переписки.

## Локальный запуск

1. Установите **Node.js 22.14 или новее** вместе с npm и **Git**. Проверьте, что команды доступны в терминале:

```bash
node --version
npm --version
git --version
```

2. Склонируйте репозиторий и перейдите в папку проекта:

```bash
git clone https://github.com/Kamballakilla/max-green-chat.git
cd max-green-chat
```

Если проект уже скачан, откройте терминал в папке с файлом `package.json`.

3. Установите зависимости из lockfile и запустите сервер разработки:

```bash
npm ci
npm run dev
```

4. Откройте **http://127.0.0.1:5173/max-green-chat/**. Если порт занят, Vite выберет другой — используйте адрес из строки `Local` в терминале. Оставьте терминал открытым, пока работаете с приложением.

5. Нажмите **«Открыть демо»**, чтобы проверить приложение без аккаунта и ключей. Для реальной переписки выполните шаги раздела «Реальное подключение» ниже. Файл `.env` и отдельный backend для запуска не нужны: параметры подключения вводятся в интерфейсе.

Остановить сервер можно сочетанием **Ctrl+C** в терминале. Для повторного запуска выполните `npm run dev` из папки проекта; повторная установка зависимостей нужна только при изменении `package-lock.json` или удалении `node_modules`.

В Windows, если PowerShell блокирует `npm.ps1`, используйте `npm.cmd ci` и `npm.cmd run dev` либо запустите те же команды в командной строке (`cmd`).

### Проверка и production-сборка

```bash
npm run check    # ESLint, тесты, TypeScript и production-сборка
npm run build    # результат в dist/
npm run preview  # локальный просмотр production-сборки
```

Перед `npm run preview` выполните `npm run build`. По умолчанию собранное приложение доступно по адресу **http://127.0.0.1:4173/max-green-chat/**; точный адрес указан в терминале. Открывать `dist/index.html` напрямую как файл не нужно — используйте preview-сервер.

## Реальное подключение

1. В [личном кабинете GREEN-API](https://console.green-api.com/) создайте **MAX-инстанс** и авторизуйте его. Состояние должно быть `authorized`.
2. В настройках инстанса включите `incomingWebhook: yes`. Поле `webhookUrl` оставьте пустым для получения через HTTP API.
3. Для статусов включите `outgoingWebhook`, `outgoingAPIMessageWebhook`, `outgoingMessageWebhook`. Рекомендуется также `stateWebhook`, чтобы получать изменения авторизации. Настройки меняются вручную: приложение их не перезаписывает.
4. Скопируйте `apiUrl`, `idInstance`, `apiTokenInstance` в форму. `apiUrl` берётся именно из кабинета: номер кластера нельзя надёжно вычислять из idInstance.
5. Нажмите «Подключиться». Клиент проверит авторизацию и настройки получения.
6. Создайте чат по номеру РФ (`+7`) или Беларуси (`+375`), отправьте текст и ответьте с телефона получателя в MAX.

Используйте отдельный тестовый инстанс и **один клиент получения**. ReceiveNotification / DeleteNotification работают с общей очередью инстанса. Другой клиент может забрать события раньше этого приложения. Обрабатываемые события удаляются из очереди после обработки; это не удаляет сообщения из MAX. Вложения, группы и неподдерживаемые события подтверждаются, но не отображаются.

## Соответствие заданию

| Требование                | Реализация                                                                                      |
| ------------------------- | ----------------------------------------------------------------------------------------------- |
| React                     | React + TypeScript + Vite                                                                       |
| Ввод учётных данных       | Форма подключения, проверка состояния и настроек                                                |
| Создание чата по телефону | `CheckAccount` → канонический MAX `chatId`                                                      |
| Отправка текста           | `SendMessage`, ограничение 4000 символов                                                        |
| Получение ответа          | Последовательный long polling `ReceiveNotification` → обработка → `DeleteNotification`          |
| Простой интерфейс         | Список диалогов, переписка, поле ввода; мобильный экран                                         |
| Прототип MAX              | Двухколоночная компоновка мессенджера, светлая тема, синие акценты, входящие/исходящие пузырьки |

Интерфейс — самостоятельная адаптация в стиле MAX со светлой темой и синими акцентами.

## Что сделано сверх минимального сценария

- **Демо без ключей** с тем же интерфейсом и общей логикой обработки событий.
- **Защита от повторных уведомлений** и от понижения статуса сообщения.
- **Ранние статусы:** `read` до HTTP-ответа отправки не теряется.
- **Восстановление получения:** экспоненциальная пауза до 30 секунд; остановка при ошибках доступа.
- **Отмена запросов** при выходе и размонтировании, включая React StrictMode.
- **Честные статусы:** принятие в очередь не выдаётся за доставку. При неоднозначной сетевой ошибке отправка автоматически не повторяется.
- **Черновики по чатам**, поиск диалогов, счётчики непрочитанного, сохранение позиции прокрутки.
- **Доступность:** подписанные поля и кнопки, native dialog с удержанием фокуса, управление клавиатурой, live region сообщений, поддержка reduced motion.
- **Тесты поведения и API-контрактов**, CI для GitHub и воспроизводимый lockfile.

## Архитектура

```text
src/
  App.tsx                  # выбор экрана подключения или активной сессии
  types.ts                 # типы домена и контракт ChatApi
  api/
    greenApi.ts            # fetch, HTTP-ошибки, проверка ответов GREEN-API
    demoApi.ts             # локальная очередь и демоданные
  hooks/useChat.ts          # состояние сессии, отправка, жизненный цикл polling
  lib/
    chatReducer.ts         # чистые переходы состояния, дедупликация и статусы
    notifications.ts       # входной unknown → типизированное событие
    polling.ts             # последовательное получение и подтверждение
    validation.ts          # телефон, адрес API, ключи, лимит текста
  components/
    Login.tsx              # подключение и инструкция
    ChatWorkspace.tsx      # список диалогов, переписка, ввод текста
    NewChatDialog.tsx      # форма нового диалога
    Brand.tsx              # общий знак приложения
  test/                    # модульные и интеграционные проверки
```

React hooks и reducer достаточны для этого объёма. Redux, роутер и сервер не добавлены: у приложения одна сессия и два основных состояния. `ChatApi` позволяет проверить интерфейс без аккаунта, не дублируя компоненты.

## Данные и ограничения

- Ключ и переписка хранятся **только в памяти**. Обновление страницы или выход очищает их. Импорта истории нет: показываются сообщения, полученные/отправленные этой сессией, в том числе оставшиеся в очереди за доступный сервису период.
- Чистый frontend выполняет запросы напрямую в GREEN-API; секрет виден владельцу браузера в Network. Не публикуйте ключи и HAR-файлы. В production-продукте с чужими аккаунтами стоит добавить backend-сессию и серверное хранение секретов.
- Токен не записывается в localStorage, логи, репозиторий или сообщения об ошибке. Адрес API ограничен HTTPS-хостами `api.green-api.com` и их поддоменами; сторонний адрес для отправки ключа не принимается.
- Текст выводится React как текст, без `dangerouslySetInnerHTML`. Вложения, звонки, редактирование, групповые чаты и синхронизация сообщений, отправленных с телефона, вне объёма задания.
- Гарантия exactly-once между браузером и внешним API недостижима без дополнительного хранилища/идемпотентности. Дедупликация работает внутри сессии. Между обработкой и подтверждением очередь может быть повторена; после подтверждения обновление вкладки не восстановит сообщения.
- Реальная работа зависит от авторизации, тарифа, ограничений поиска номера, доступности GREEN-API и CORS сервиса. Ни демо, ни mock-тесты не заменяют проверку двумя реальными аккаунтами.
